## 理解を確かめる問い

次のいずれかの思考を必要とする問題を優先する。

| 思考 | 問いの形 | 確かめられること |
|---|---|---|
| 予測 | 「Xが失敗または変更されたら、次に何が起きるか」 | 因果関係の理解 |
| 選択 | 「制約Xがあるとき、BではなくAを使う理由は何か」 | トレードオフの理解 |
| 追跡 | 「この値はどこから入り、どこで変わり、どこへ保存されるか」 | データまたは制御の流れ |
| 配置 | 「この責務はどのコンポーネントが持つべきか」 | 設計上の境界 |
| 診断 | 「AとBを見分けるには、何を観察すればよいか」 | 障害の切り分け方 |
| 検証 | 「この性質を確認するには、どのようなテストが必要か」 | 成功条件 |
| 変更 | 「要件Xが変わったら、どこを変更する必要があるか」 | 別の状況への応用と保守性 |

定義や用語を問う問題は、これらの思考に進むための短い足場としてだけ使う。

## プランを扱う順序

システムの目的から始め、次の順で内部へ進む。

1. 目的と制約
2. アーキテクチャと責務の境界
3. 技術選択とトレードオフ
4. 実装の仕組み
5. 障害の起こり方と検証方法

利用者が直面している実装判断を先に扱うほうが役立つ場合は、この順序を変える。

## 難易度の調整

### 基礎

二つまたは三つの選択肢を示し、短い理由を求める。
プランから答えまでの因果関係は一段にする。

例：

```text
このプランでは、APIとの境界で入力を検証します。
この位置で検証する主な目的は何でしょう？
```

### 実務で使える理解

動作の予測または現実的な代替案の比較を求める。
二つの考えをつなげないと答えられない問題にする。

例：

```text
データベースアダプターの内部だけで入力を検証すると、どの呼び出し元で動作が不統一になり得ますか？
その理由も説明してください。
```

### 別の状況への応用

制約を一つ変え、プランをどのように変えるべきかを問う。
トレードオフを説明できる場合は、複数の妥当な設計を認める。

例：

```text
このエンドポイントが後から一括入力を受け付ける場合、どの検証境界を残し、どの境界を追加しますか？
```

## 出題前に決める評価基準

利用者へ見せずに、次の内容を整理する。

- 答えに必要な考え
- 妥当な代替案とその根拠
- 起こりやすい誤解
- 答えを裏付けるプラン上の記述
- 誤解を修正する、より単純な問題

利用者が答える前に、この評価基準を開示しない。

## 回答の型ごとの診断

### 選択は正しいが理由が弱い場合

「根拠が弱い」と判定する。
どのような結果が生じるか、または最も近い代替案がなぜ合わないかを尋ねる。

### 選択は異なるが理由が妥当な場合

出題元のプランに、その案を除外する制約があるかを確かめる。
制約がなければ、プランへの妥当な異論として認める。

### 用語だけを知らない場合

専門用語を使わずに説明し直し、動作から考えられるようにする。
用語を知らないことだけを理由に評価を下げない。

### 広すぎて曖昧な回答の場合

データの流れ、障害、ファイル間の境界、テストのいずれか一つを具体的に尋ねる。

### 「わからない」という回答の場合

次の順でヒントを一つずつ示す。

1. 関係する制約を示す。
2. 二つの具体的な結果を比較する。
3. 仕組みを短く説明する。

説明後は条件を変えた応用問題を出す。

## 誤解を招く問題の回避

次の問題は作らない。

- プランやリポジトリにない詳細を問う問題
- 採用した設計が常に最善だと示唆する問題
- 正解が複数あるのに一つだけ選ばせる問題
- 言葉のひっかけや否定を重ねた選択肢
- 構文自体がリスクになる場合を除き、正確な構文を暗記させる問題
- 一回で複数の独立した論点を問う問題
- 自信、回答速度、流暢さを理解度とみなす問題

## 対話例

```text
問題 1：状態の置き場所
このプランでは、画面のフィルター条件をURLに保存します。
コンポーネント内部の状態だけに保存する案と比べた主な利点は何でしょう？

A. 再描画が必ず減る
B. URL共有や戻る操作で同じ状態を再現できる
C. API通信が不要になる

答えと、その理由を一言で教えてください。
```

「B。URLが再現可能な入力になるから」と答えた場合は、「理解できている」と判定する。
回答をルーティングとテスト時の動作に結び付けて説明する。

「B。URLのほうが速いから」と答えた場合は、「根拠が弱い」と判定する。
再現できることが理由だと説明し、ブラウザの「戻る」操作後に何が起きるべきかを尋ねる。
