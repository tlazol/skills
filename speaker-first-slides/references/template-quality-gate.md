# テンプレート使用時の品質同等性ゲート

指定テンプレートを使う新規作成、変換、再設計、または比較レビューで読む。ブランド忠実度を守りながら、テンプレートなしで設計した場合の登壇品質を下回らないために使う。

## 1. 先に品質基準を固定する

テンプレートを開く前に、話の背骨と各スライドの役割を決める。各ページについて次を1行ずつ記録する。

- 話の役割: 導入、解説、比較、工程、演習、確認、振り返り、行動など
- 主要な主張: そのページで聴衆に残す1点
- 必要な構図: 例として、強い導入、縦リストと焦点画像、左右比較、工程、操作開始、確認
- ワンポイントイラストの役割: 何を理解または記憶させるか。表紙には割り当てず、表紙以外の全ページに1点ずつ割り当てる
- 横並び理由: 横方向の位置自体に意味がある図解を使う場合のみ

同じ内容のテンプレートなし版、旧版、PDF、参考画像がある場合は、全ページをレンダリングして `quality-baseline.txt` に次の基準を記録する。参考資料の配色や部品を指定テンプレートへ混在させない。

- 最初に目へ入る要素と情報階層
- 主要文字を把握するまでの速さ
- 焦点ビジュアルの意味と大きさ
- ページ間の構図、明暗、密度の変化
- 導入、説明、演習、確認、結論の見分けやすさ

比較対象と最終版のページ数や分割が異なる場合は、ページ番号を1対1で比べない。`quality-baseline.txt` に「主要な主張、演習、確認、結論 → 比較対象ページ → テンプレート版ページ」の対応も記録し、内容の欠落と重複を先に確認する。

比較対象がない場合は、`layout-recipes.md` と選択した密度プロファイルを品質基準にする。

## 2. テンプレートの能力を監査する

Presentations スキルのテンプレート追従手順で、全ソーススライド、マスター、レイアウト、プレースホルダー、画像枠、ブランド要素を検査する。ソーススライドの見た目だけでなく、編集可能な領域と継承関係を確認する。

マスター内に多数のレイアウト定義があっても、形式別スキルが元スライドの複製と編集を要求する場合は、実スライドとして使用例と編集可能な枠が存在しないレイアウトを「利用できる型」に数えない。未使用レイアウトの存在だけで十分なテンプレートと判定しない。

`template-audit.txt` に次の表を作る。

| 必要な話の役割 | 利用できる元スライド | 編集できる領域 | 品質基準を満たすか | 対応 |
| --- | --- | --- | --- | --- |
| 導入 | 例: 1 | タイトル、補助文 | はい | 複製 |
| 工程 | なし | なし | いいえ | 不足時フロー |

テンプレートを次のどちらかに分類する。

- **十分**: 必要な話の役割を、情報階層と構図を崩さず支える元スライドがある。
- **薄い**: 表紙、アジェンダ、ロゴ終端など用途が限定された型しかない、または必要な役割の編集領域がない。

たとえば、実スライドが「表紙、アジェンダ、ロゴ終端」だけで、解説、工程、演習、確認が必要なら薄いテンプレートとする。アジェンダを汎用本文として十数枚複製して解決しない。

## 3. 話の役割を元スライドへ割り当てる

話の役割から元スライドを選び、形式別スキルが要求するフレームマップへ記録する。次を守る。

- アジェンダ型は、項目の全体像や順序を示す場合だけに使う。
- ロゴ終端は、内容上の結論を終えた後だけに使う。
- 表紙型を章扉へ再利用する場合は、元の情報階層とブランド要素を壊さず、実際のモード転換に限る。
- 汎用本文型が続く場合も、焦点位置、画像比率、本文開始位置を話の役割に合わせて変える。形式別スキルが変更を許さない場合は、別の元スライドを選ぶ。
- 同じシルエットが4枚以上続くのは、位置関係を保つ段階的な説明だけにする。単なる話題の連続なら再割り当てまたは分割を行う。
- 画像や本文を少し動かしただけの装飾的な差を、構図の変化として数えない。サムネイルで導入、説明、演習、確認、結論の役割を識別できる変化だけを数える。

## 4. 型が不足する場合に品質を守る

必要な役割を支える型がない場合は、次の順で解決する。

1. 別の元スライドへ割り当てる。
2. 文言を短くするか、1話題1枚へ分割する。
3. 形式別スキルが許す場合だけ、継承された編集領域内で焦点ビジュアルや必要最小限の要素を追加し、範囲と理由を逸脱記録へ残す。
4. 解決できなければ、必要な役割を持つ追加例スライドを含むテンプレートを求める。
5. 利用者がテンプレート指定を取り下げる場合だけ、形式別スキルが許す別の明示的な視覚方針へ切り替える。指定 PPTX の部品を流用または模倣して、テンプレートを使ったことにしない。
6. どちらも選ばれない場合は、足りない型、影響するページ、必要な入力を報告して止める。

文字を縮小する、焦点画像を小さくする、余白へ本文を散らす、アジェンダ型を万能化する方法で不足を隠さない。

表紙以外でテンプレートに挿絵領域がなくても、ワンポイントイラストを省略しない。継承領域内で本文を短縮または分割して配置できなければ、そのテンプレートでは完成不可とし、不足時フローへ戻る。

## 5. 実装中にリズムと焦点を保つ

- 焦点ビジュアルは、透明余白を除いた被写体の外接矩形が通常の解説ページでスライド幅の28〜40%または高さの40〜65%を占める大きさを目安にし、一覧でも話題を識別できる大きさにする。
- 本文と安全余白を確保した後も大きな空き領域が残る場合は、本文と競合しない範囲まで焦点ビジュアルを拡大する。画像枠や透明キャンバス全体の寸法で大きさを判定しない。
- テンプレートのロゴ、背景模様、フッターを焦点ビジュアルへ数えない。
- 表紙にはワンポイントイラストを追加しない。章扉、コード、グラフ、スクリーンショットを含む表紙以外の全ページに、ページ固有のワンポイントイラストをちょうど1点入れる。
- 複数の本文項目は単一の縦リストへまとめる。テンプレート由来のカード列や複数列へ分散させない。
- 横並びは、比較、時系列、工程、因果関係のように位置自体が意味を持つ図解だけに使い、発表者ノートへ理由を記録する。
- 導入、演習開始、注意、結論など話のモードが変わるページでは、テンプレート内の別型、焦点位置、明暗、密度のいずれかを変える。
- ブランドの装飾が強い場合は、追加画像と競合させない。本文、装飾、画像の3焦点を作らない。
- テンプレートの余白を埋めるためだけに小さなアイコンや図を置かない。
- 表紙以外でブランド装飾とワンポイントイラストが競合する場合は、本文の短縮、ページ分割、挿絵の簡略化または配置変更で焦点を整理する。挿絵の省略や過度な縮小で解決しない。

## 6. 品質同等性を判定する

最終版と品質基準を一覧表示と実寸表示で比較し、`quality-parity-review.txt` に記録する。

| 観点 | 合格条件 |
| --- | --- |
| 情報階層 | 各ページで主張、根拠、補助情報の順が一目で分かる |
| 可読性 | テンプレートなし版または密度基準より把握が遅くならない |
| 焦点ビジュアル | 表紙はワンポイントイラスト0点、表紙以外はちょうど1点で、意味があり、一覧でも識別でき、本文と競合しない |
| 構図の変化 | 話の役割が変わる箇所を画面の変化から識別できる |
| 話のテンポ | 導入、説明、演習、確認、結論の節目が単調な反復へ埋もれない |
| ブランド忠実度 | 指定テンプレートの継承要素、書体、色、ロゴ、余白を壊していない |

形式別スキルの複製・編集契約、ブランド忠実度、上表の品質同等性をすべて同時に満たすことを合格条件にする。いずれかが両立しない場合は完成不可とし、不足時フローへ戻る。

次のいずれかがあれば不合格とする。

- 表紙にワンポイントイラストがある、または表紙以外に0点または2点以上のページがある。
- 箇条書きが横並びのカード、複数列、散在したラベルとして配置されている。
- 横並びのページに位置関係の意味または発表者ノート上の理由がない。
- 同じ本文型が4枚以上続き、段階的説明としての理由がない。
- アジェンダ型を解説、演習、確認へ流用している。
- 挿絵が余白の飾りになるほど小さく、一覧で判別できない。大きな空き領域があるのに拡大されていない。
- テンプレートなし版よりタイトルの強弱、視線誘導、場面転換が明確に弱い。
- 忠実度検査や構造監査だけを根拠に完成としている。

不合格なら、元スライドの再割り当て、ページ分割、文言短縮、焦点ビジュアルの再配置を行って再レンダリングする。テンプレートの能力不足が原因なら、不足時フローへ戻る。
